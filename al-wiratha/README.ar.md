# ورثة | Warathah

**منصة إدارة التركات والميراث الإسلامي**

ورثة هي منصة متكاملة لحساب أنصبة الإرث الإسلامي (الفرائض) وفق المذاهب الأربعة، وإدارة التركات المشتركة بين الورثة، وتتبع توزيعات الإيرادات الإيجارية، وتشغيل حملات التبرع الشفافة للأوقاف، مع الاحتفاظ بسجل تدقيق غير قابل للتعديل لكل إجراء.

## نظرة عامة

**ورثة** (من الكلمة العربية التي تعني "الوارثون") تحل التعقيدات الحقيقية في إدارة التركات الإسلامية:

1. **حاسبة المواريث** — أدخل بيانات الورثة وقيمة التركة واحصل على الأنصبة الكسرية الدقيقة (مثل: 3/24) والمبالغ النقدية مع التوضيح الفقهي لكل وارث، بدعم كامل للمذاهب: الحنفي، والمالكي، والشافعي، والحنبلي.
2. **فضاء إدارة التركة** — مساحة تعاونية تتيح دعوة الورثة وتسجيل الأصول والإيرادات الإيجارية وصرف التوزيعات آلياً وفق الأنصبة.
3. **المقترحات والتصويت** — يصوّت الورثة على قرارات التركة (البيع، التجديد، التأجير) بنظام النصاب المرجَّح بالحصص.
4. **الوقف والتبرعات** — حملات تبرع شفافة للمساجد والأوقاف مع دفتر حسابات المصروفات الكاملة.
5. **سجل التدقيق** — كل تغيير في الحالة يُسجَّل في جدول audit_log غير القابل للتعديل بالقيم القديمة والجديدة.

## التشغيل السريع باستخدام Docker Compose

```bash
# 1. استنسخ المستودع
git clone https://github.com/your-org/warathah.git
cd warathah/al-wiratha

# 2. انسخ قالب متغيرات البيئة وعدّل الأسرار
cp .env.example .env
# افتح ملف .env وضع JWT_SECRET و DB_PASS بقيم آمنة

# 3. ابنِ جميع الخدمات وشغّلها
docker compose up --build -d

# 4. تحقق من حالة الخدمات
docker compose ps
# يجب أن تظهر الخدمات الثلاث بحالة "healthy" أو "running"

# 5. افتح التطبيق
# الواجهة الأمامية:  http://localhost:3000
# الخادم الخلفي:     http://localhost:8080/api/v1
# Swagger UI:        http://localhost:8080/api/v1/swagger-ui.html
```

لإيقاف جميع الخدمات:
```bash
docker compose down
```

لإيقاف الخدمات وحذف جميع البيانات (بما فيها قاعدة البيانات):
```bash
docker compose down -v
```

## الإعداد اليدوي

### الخادم الخلفي (Spring Boot)

```bash
cd backend

# تأكد من تشغيل PostgreSQL 16 وإنشاء قاعدة البيانات
psql -U postgres -c "CREATE DATABASE warathah;"
psql -U postgres -c "CREATE USER warathah WITH PASSWORD 'warathah';"
psql -U postgres -c "GRANT ALL PRIVILEGES ON DATABASE warathah TO warathah;"

# ضع متغيرات البيئة
export DB_URL=jdbc:postgresql://localhost:5432/warathah
export DB_USER=warathah
export DB_PASS=warathah
export JWT_SECRET=warathah-secret-key-change-in-production-must-be-at-least-256-bits-long
export ALLOWED_ORIGINS=http://localhost:3000

# بناء المشروع
mvn clean package -DskipTests

# تشغيل الخادم
java -jar target/*.jar
# الخادم متاح على http://localhost:8080
```

ترقيات Flyway (V1–V5) تعمل تلقائياً عند بدء التشغيل. لا يلزم تنفيذ أي SQL يدوياً.

### الواجهة الأمامية (Next.js)

```bash
cd frontend

# تثبيت الاعتماديات
npm ci

# ضع رابط الـ API
export NEXT_PUBLIC_API_URL=http://localhost:8080/api/v1

# وضع التطوير (إعادة تحميل فورية)
npm run dev
# افتح http://localhost:3000

# بناء الإنتاج
npm run build
npm start
```

## متغيرات البيئة

انسخ `.env.example` إلى `.env` واملأ القيم:

| المتغير | القيمة الافتراضية | الوصف |
|---|---|---|
| `DB_USER` | `warathah` | اسم مستخدم PostgreSQL |
| `DB_PASS` | `warathah_secure_password_here` | كلمة مرور PostgreSQL — غيّرها في الإنتاج |
| `JWT_SECRET` | *(قيمة مثال)* | مفتاح توقيع HS256 — يجب أن يكون 256 بت على الأقل (32 محرفاً) |
| `NEXT_PUBLIC_API_URL` | `http://localhost:8080/api/v1` | رابط API الخلفي المرئي للمتصفح |
| `ALLOWED_ORIGINS` | `http://localhost:3000` | النطاقات المسموح بها في إعدادات CORS |

> **تنبيه أمني:** لا تُضف ملف `.env` إلى Git أبداً. فهو مدرج في `.gitignore`.

## ترقيات قاعدة البيانات

تُدار الترقيات بواسطة **Flyway** وتعمل تلقائياً عند بدء تشغيل التطبيق.

| الإصدار | الملف | الوصف |
|---|---|---|
| V1 | `V1__create_users.sql` | جدول المستخدمين ورموز التحديث |
| V2 | `V2__create_inheritance.sql` | حالات الميراث وجدول case_heirs |
| V3 | `V3__create_estates.sql` | التركات، الأعضاء، الأصول، التوزيعات، المقترحات، الأصوات، المصروفات |
| V4 | `V4__create_waqf.sql` | الجهات الوقفية، الحملات، التبرعات، مصروفات الوقف |
| V5 | `V5__create_audit_log.sql` | سجل التدقيق غير القابل للتعديل مع RLS |

ملفات الترقية موجودة في:
```
backend/src/main/resources/db/migration/
```

## المساهمة في المشروع

نرحب بمساهمات المجتمع. يرجى اتباع الخطوات التالية:

1. **انسخ (Fork)** المستودع وأنشئ فرعاً من `main`:
   ```bash
   git checkout -b feature/اسم-الميزة
   ```

2. **أسلوب الكود**
   - الخادم الخلفي: اتبع Google Java Style Guide؛ نفّذ `mvn checkstyle:check` قبل الإيداع.
   - الواجهة الأمامية: ESLint + Prettier؛ نفّذ `npm run lint` قبل الإيداع.

3. **الاختبارات**
   - الخادم الخلفي: `mvn test` — اختبارات الوحدة لمحرك الفرائض إلزامية عند أي تغيير في منطق الإرث.
   - الواجهة الأمامية: `npm test`

4. **رسائل الإيداع (Commit)** تتبع معيار Conventional Commits:
   ```
   feat(inheritance): إضافة حساب العول للمذهب الحنفي
   fix(distribution): تصحيح التقريب عند زيادة الورثة عن 12
   docs: تحديث README بنقاط نهاية الوقف
   ```

5. **طلب الدمج (Pull Request)**
   - استهدف الفرع `main`.
   - أكمل نموذج الـ PR (ماذا، لماذا، كيفية الاختبار).
   - يلزم موافقة مراجع واحد على الأقل قبل الدمج.

6. **تغييرات الفقه الإسلامي** تتطلب الاستشهاد بمرجع فقهي كلاسيكي (مثل: المغني لابن قدامة، أو المجموع للنووي) في وصف الـ PR.
