# وثيقة تسليم فني — منصة ورثة (Al-Wiratha)

> وثيقة مرجعية للفريق المستلِم. تشرح **ماذا بُني ولماذا** — القرارات المعمارية وأسبابها،
> والمزالق (gotchas)، وكيفية التشغيل والنشر، والبنود المفتوحة. اقرأها كاملة قبل التعديل.

## 1. ما هي المنصة وتموضعها

منصة **ورثة** = أداة لإدارة التركات والعقارات المشتركة بين الورثة + حاسبة مواريث شرعية.

**التموضع الاستراتيجي (مهم لأي قرار منتج):** منصات وزارة العدل (ناجز، منصة التركات، تراضي)
تعمل على **الحدث** (حصر ← قسمة ← إغلاق الملف). ورثة تعمل على **العلاقة المستمرة**: إدارة
العقار المشترك بعد القسمة لسنوات (إيرادات، تصويت، مستندات). شعار التموضع:
«وزارة العدل تُغلق ملف القسمة — وورثة تفتح ملف الإدارة». لا تنافس منصات الوزارة في الحساب،
بل تكمّلها فيما بعده.

## 2. المعمارية والتقنيات — ولماذا

| التقنية | الإصدار | لماذا |
|---------|---------|-------|
| Next.js | **16** (App Router) | SSR + Route Handlers + RSC. **تحذير:** إصدار به breaking changes |
| TypeScript | — | أمان الأنواع عبر المحرك المالي والفقهي |
| Prisma | **7** | ORM؛ إصدار 7 يتطلب **adapter صريح** لـ SQLite |
| SQLite | via better-sqlite3 | بساطة النشر؛ **قيد: نظام ملفات — يحتاج Volume دائم عند النشر** |
| Tailwind CSS | — | RTL كامل + سرعة بناء الواجهة |
| jose | — | توقيع/تحقق JWT (يرفض alg=none والتوقيع الفاسد) |
| bcryptjs | — | تجزئة كلمات المرور |
| Zod | **v4** | تحقق المدخلات — **ملاحظة: v4 تستخدم `.issues` لا `.errors`** |

### مزالق حرجة يجب معرفتها (أهم قسم للفريق الجديد)
1. **Next.js 16 استبدل `middleware` بـ `proxy`**: الملف `src/proxy.ts` والدالة اسمها `proxy` (لا `middleware`). ملف `AGENTS.md` في الجذر ينبّه: راجِع `node_modules/next/dist/docs/` قبل الكتابة.
2. **Prisma 7 + SQLite**: يجب تمرير `PrismaBetterSqlite3` adapter في `src/lib/db.ts` — لا يعمل بدونه («requires adapter or accelerateUrl»). المُنشئ: `new PrismaBetterSqlite3({ url: absolutePath })`.
3. **سرّ JWT إلزامي في الإنتاج**: `src/lib/jwt-secret.ts` **يرمي خطأ عند الإقلاع** إن غاب `JWT_SECRET` في الإنتاج (حماية مقصودة). fallback ثابت للتطوير فقط. `proxy.ts` و`auth.ts` حزمتان منفصلتان في Next 16 فيستوردان السرّ من ملف واحد مشترك.
4. **الأموال بالهللات (Int) لا Float**: كل المبالغ المخزَّنة أعداد صحيحة (هللة = 1/100 ريال). لا تُدخِل حسابات عشرية على المبالغ المخزَّنة.
5. **مجلدات `frontend/` و`backend/` القديمة**: مشروع Java/Spring قديم موازٍ (نسخة سابقة) — مُستثنى من `tsconfig` و`.dockerignore`. **لا علاقة له بالمنصة الحالية.**

## 4. نماذج البيانات (`prisma/schema.prisma`)

- **User**: المستخدم (name, email, password مجزّأ, phone, nationalId, role). الدور الافتراضي **HEIR** (التفويض على مستوى العقار لا الدور العام).
- **Estate**: العقار/التركة (name, type, value, adminId, status). status يشمل `ARCHIVED` (حذف ناعم).
- **HeirShare**: حصة وريث (shareNumerator/Denominator + sharePercentage + relation) — **الكسر الدقيق مخزَّن** ويُستخدم في التوزيع.
- **RentalIncome / Distribution**: الإيراد وتوزيعه. المبالغ **Int (هللات)**. Distribution له status (PENDING/PAID) + paidAt + paymentRef.
- **Proposal / Vote**: التصويت المرجّح (weight = نسبة الحصة).
- **Expense**: المصروفات بالهللات مع تصنيف (صيانة/زكاة/رسوم/أتعاب/تأمين).
- **HeirInvite**: دعوة آمنة برمز عشوائي وصلاحية 14 يوماً (بدل كلمة مرور ثابتة).
- **ActivityLog**: سجل التدقيق (من فعل ماذا ومتى).
- **Document**: خزنة المستندات (صك حصر الورثة، الصكوك...). الملفات على قرص عبر `UPLOADS_DIR`.
- **Notification**: إشعارات داخلية.
- **AnalyticsEvent**: تتبّع القمع (first-party، بدون خدمات خارجية).

**cascade:** روابط الأبناء على العقار `onDelete: Cascade` (بما فيها Distribution←RentalIncome وVote←Proposal بعد الإصلاح).

## 5. المصادقة والتفويض — ولماذا بهذا الشكل

- **الجلسة**: JWT في cookie باسم `al-wiratha-token` (httpOnly, secure في الإنتاج, 7 أيام).
- **حماية المسارات**: `src/proxy.ts` — قائمة `PUBLIC_PATHS` (الرئيسية، الحاسبة، القانونية، sitemap/robots) و`API_PUBLIC`. الباقي يتطلب جلسة.
- **التفويض على مستوى العقار**: `src/lib/authz.ts`:
  - `requireEstateMember(estateId, userId)` — للأعضاء (مدير أو صاحب حصة).
  - `requireEstateAdmin(...)` — للمدير فقط.
  - **قرار مهم:** يُرجَع **404 للغرباء (لا 403)** — حتى لا يُكشف وجود العقار أصلاً (منع IDOR وتسريب الوجود). و403 للعضو غير المدير.
- **تحديد معدّل الدخول** (`rate-limit.ts` + `client-ip.ts`): الأساس على البريد (لا يُزوَّر)؛ الـ IP يُعتمد فقط خلف بروكسي موثوق (`TRUSTED_PROXY=true`) لأن `X-Forwarded-For` قابل للتزوير.

## 6. ⭐ محرك المواريث (`src/lib/inheritance.ts`) — القلب

الدالة العامة: `calculateInheritance(input: HeirInput, mode: CalcMode, estateValue?)`.

### أوضاع الحساب (`CalcMode`)
`"SAUDI"` (الافتراضي) | `"HANAFI"` | `"MALIKI"` | `"SHAFII"` | `"HANBALI"`.
- **النظام السعودي**: يعتمد المرجعية الحنبلية عموماً، **لكن الجدُّ يحجب الإخوةَ** (قول أبي حنيفة/ابن تيمية، المادة 212 من نظام الأحوال الشخصية). داخلياً: `madhab=HANBALI` + `grandfatherBlocksSiblings=true`.
- المذاهب الأربعة متاحة للمقارنة التعليمية؛ الواجهة تُظهر تنبيهاً عند اختيار مذهب مخالف للنظام.

### ما يُعالجه المحرك (كلها مختبَرة بحالات فرائض معروفة الأنصبة)
- الفروض المقدّرة والتعصيب (للذكر مثل حظ الأنثيين).
- **العول** (`furudSum>1` → تُقلَّص الأنصبة بنسبة واحدة).
- **الرد** (الباقي يُرَد على أصحاب الفروض عدا الزوجين؛ **الشافعي**: الباقي لبيت المال).
- **الحجب** (الأب/الابن يحجبان الإخوة والأجداد؛ قائمة `blockedHeirs` للشفافية).
- **العُمريّتان/الغرّاوان**: (زوج/زوجة + أم + أب) → الأم **ثلث الباقي** (1/6 مع الزوج، 1/4 مع الزوجة) — لا ثلث الأصل.
- **العصبة مع الغير**: الأخت (شقيقة/لأب) مع البنات تصير عصبة تأخذ الباقي.
- **مقاسمة الجد مع الإخوة**: الجد يأخذ الأحظّ من (المقاسمة كأخ / ثلث الباقي / سدس التركة).
- **الأكدرية** (`computeAkdariyya`): جد + أخت واحدة + صاحب فرض → قول زيد (فرض للأخت النصف وللجد السدس، عول، ثم دمج نصيبيهما واقتسامهما 2:1). في النظام السعودي/الحنفي: الجد يحجب الأخت فلا أكدرية.
- **موانع الإرث**: قسم إرشادي في الحاسبة (القتل/اختلاف الدين/الرق) — القاعدة: الممنوع لا يرث **ولا يحجب** فيُستبعد من الإدخال.

### قيود المحرك (حالات موقوفة — غير منفّذة عمداً، معروضة كـ«تحتاج مختصاً»)
المناسخة، الحمل، المفقود، الخنثى المُشكِل. لم تُنفَّذ لأن تنفيذها الناقص يضلّل؛ الحاسبة توجّه لمختص.

### ملاحظة للفريق
النموذج قائم على **الأعداد** لكل نوع وريث (لا أفراد). أي إضافة (كخنثى/مفقود) تحتاج توسعة النموذج.
`HeirResult` فيه `mode` (للتمييز بين النظام السعودي والمذاهب في الواجهة) — لا تستخدم `madhab` للـ key.

## 7. الأموال بالهللات (`src/lib/money.ts`)

- كل المبالغ **أعداد صحيحة (هللات)** — لا Float مطلقاً على المخزَّن. `riyalsToHalalas` / `halalasToRiyals` / `formatHalalas`.
- **التوزيع بخوارزمية largest-remainder** على الكسور الشرعية الدقيقة → مجموع التوزيعات = الإيراد **للهللة الأخيرة** (لا فقدان ريالات).
- **الوصية والديون** (`estate-rights.ts`): الترتيب الشرعي = تجهيز ← ديون ← وصية (بحدّ ثلث ما بعد الديون) ← الصافي للورثة. يكشف تجاوز الثلث واستغراق الديون للتركة.

## 8. وحدة إدارة التركة (لوحة التحكم)

- **العقارات** (`/estates`): إنشاء/عرض/تفاصيل/أرشفة. أرقام «الإجمالي» تُحسب بـ aggregate على كل السجلات (لا آخر 5).
- **الورثة** (`/estates/[id]/heirs`): إضافة بالكسر الشرعي + أنصبة جاهزة (½ ¼ ⅛...) + **دعوة آمنة** (رمز يُرسَل واتساب) + شارة «بانتظار التفعيل». واجهة الإدارة مخفية عن غير المدير.
- **الإيرادات والمصروفات** (`/estates/[id]/income`): تسجيل الإيراد (مدير فقط) → توزيع ذري في `$transaction` → **تأكيد الدفع** «تم التحويل» (PATCH distributions) + المصروفات والصافي.
- **التصويت** (`/estates/[id]/votes`): وزن الصوت = الحصة، قائمة علنية بالمصوّتين، عدّاد الأيام، حسم تلقائي (lazy-close للمقترحات المنتهية، سياسة التعادل=مغلق).
- **كشف حساب الوريث** (`/statement`): «كام نصيبي وفين فلوسي» عبر كل التركات + طباعة.
- **سجل النشاط + خزنة المستندات + الإشعارات**: في تفاصيل العقار.

## 9. الحاسبة العامة والقياس

- **الحاسبة** (`/calculator`): عامة بدون تسجيل، تحسب **داخل المتصفح** (لا تُرسل مدخلات للخادم). بعد النتيجة: خطّاف «احفظ النتيجة وأنشئ التركة» (يحفظ مسودة في localStorage تُستعاد بعد التسجيل) + مشاركة/طباعة بهوية المنصة.
- **التتبّع** (`analytics-client.ts` + `/api/track`): قمع first-party (زيارة ← حساب ← حفظ ← تسجيل) بقائمة أحداث مسموحة + rate limiting. صفحة `/analytics` لمالك المنصة (أقدم حساب).
- **SEO**: sitemap.ts, robots.ts, Open Graph, Structured Data (FAQ + WebApplication).
